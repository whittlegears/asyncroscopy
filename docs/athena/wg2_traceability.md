## Agent results on this machine

Laptop with a 6 GB GTX 1660 Ti and 16 GB RAM, Ollama, twin stack as in `docs/Operation/quickstart.md`, 2026-10-27/28.

**Valid tool calls**: 20 instrument requests, scored on the right tool with schema-valid arguments (`benchmarks/results/tool_json.json`).

| Model | Valid | Time for 20 |
| :-- | --: | --: |
| qwen3:8b (default) | 95 % | 218 s |
| qwen3:4b | 100 % | 301 s |

**Mapping trials** (`benchmarks/run_mapping_trials.py`). A trial passes when:

- the map completes with a stitched map key;
- the stage box covers the requested area without being far larger;
- EDS is used exactly when asked;
- interesting regions are scored exactly when asked.

| Task | `mapping` graph (model plans, graph runs the workflow) | `general` agent (model makes every call, using the mapping skill) |
| :-- | --: | --: |
| Map a 600 nm square | 9/10 | 10/10 |
| ... with an EDS spectrum per tile | 10/10 | 10/10 |
| ... and find the 3 most interesting regions | 10/10 | 10/10 |
| Stage moves outside a plan box (all trials) | 0 | 0 |

The `general` column is the sixth round (10 trials per task, qwen3:8b). Overall it went 0/15, 1/15, 6/14 (one model-server crash not counted), 7/15, 13/15, then 30/30. These changes moved it:

- The Mapper accepts a plan's size and does the box arithmetic (`size_m`).
- Every refused plan comes back with a valid example.
- `wait_for_job` replaces dozens of status polls.
- The prompt tells the agent to act instead of announcing.
- The skill is explicit about stitching and scoring.
- `wait_for_job` and `analysis_job_status(wait_s=...)` wait on the server, and each names the other when given the wrong kind of job id.
- `score_map` accepts a per-axis `window_m` list.
- The prompt is generic when no STEM tools are connected, and skills are listed only when their required tools exist.

After the review fixes (refusing plans with no area, Mapper discovery, the allow-list stop rule, shorter tool descriptions), final checks on the same stack gave the `mapping` graph 15/15 and then 9/9 on the last commit, and the `general` agent 3/3 and then 8/9 (the miss waited on an analysis job with the instrument's `wait_for_job` and lost track), with no stage move outside a plan box. Further rounds of adversarial review followed (code quality, new-instrument translatability with an XRD and an optical example built from the docs alone, and fresh clone runs by a newcomer on Windows without uv on PATH), each round's fixes re-reviewed until no high- or medium-severity finding remained. The last rounds hardened the safe-stop allow-list (a bare `Off`, `disengage_motor`, `retract_shutter` and beamstop commands are held), job reservations against failed state saves, and the PowerShell background start and stop. The general agent completed 30 of 30 trials across two runs on 8ca4040 (`benchmarks/results/mapping_trials_general_final2.json`, `..._final3.json`) and 15 of 15 on f79842f (`..._final4.json`, which differs from 5ac5809 only in a job-start rollback and docs), and the `mapping` graph 9 of 9 on 5ac5809 (`..._graph_final3.json`), with no stage move outside a plan box; the CLI `mapping` run took 141 s for 25 tiles with EDS; `check_stack.py` and `check_gui_contract.py` (13/13) passed on a stack started with the quickstart's PowerShell recipe, and its stop command cleared a stack whose launcher had been killed (33 orphaned device servers). On 5ac5809 the desktop GUI listed the stitched maps, showed the agent's EDS map with its 25 points and a point's spectrum, switched the instrument to approve mode, showed a held `Mapper_start` with its plan, approved it (traced as the GUI's operator), the agent's retry ran 9 of 9 tiles, and the GUI switched the instrument back to auto. Thirty trials are a small sample, and earlier rounds failed by stopping after collecting data, skipping scoring, or adding EDS nobody asked for. Use the `mapping` graph when the workflow is known; the general agent is for open-ended requests. Raw rows, including the tools called and skills loaded per trial: `benchmarks/results/mapping_trials_*.json`.

**Workflow suite** (`benchmarks/run_workflows.py`, 31 twin workflows, general agent, qwen3:8b, one run each). The first full run (0e05e2d) passed 16 of 31. After its fixes, 6020db0 passed 21 of the 27 that ran (4 did not start: a benchmark setup bug). Each later round re-ran only the workflows still failing, on that round's fixes, and fixed what the failures showed:
- f6e82bc/60c8d77 (4 of 10): fixes for the mapping graph and the benchmark setup, refusal of one-tile maps, revisit-only plans in the explore skill, and a loop guard for agents that cycle through the same calls.
- c544ac1 (2 of 6): the checks now count a map job's own revisits.
- 25db03d (0 of 4) and 367d2f2 (0 of 2): `list_pois` takes `kind="all"` and several kinds at once; `run_job` takes `wait=false`, which an agent needs to start a map it may stop.
- 01006e9 (2 of 2): an abort reply names the exact resume call.

On its latest run, every workflow passes except `survey_rank_and_analyse` and `focus_series`. Both failures are the model's: it named no elements for a spectrum it had not looked at, and it skipped the final "set the defocus back to 0" while saying it had done it. These passes come from different commits and a single run each, so read them as coverage, not a success rate. After the full-code, translatability and clone reviews, all 31 ran again on one commit (8539eb6): 28 of 31 passed (`benchmarks/results/workflows_twin_general_8539eb6.json`). The three misses were the model's: `focus_series` skipped resetting the defocus while reporting it had, `survey_rank_and_analyse` placed the beam outside its 0 to 1 range and never took the spectrum, and `cuj3_three_regions_high_mag` scored one region where three were asked for. Re-running the three misses after fixing what they showed (revisits near the box edge imaged off centre, a revisit plan in the wrong shape answered with the right one, place_beam refusing stage metres with the way to reach a stage point, acquisitions returning their text summary) left them failing on the model's choices: survey_rank_and_analyse now reaches the spectrum but does not name its elements, and cuj3 scores the map with arguments that yield one region (the scorer with defaults returns three); the spectrum and image workflows still pass (6 of 6, `benchmarks/results/workflows_twin_general_4265f15.json`). With the claim check on (af751d0, which corrects a final answer that claims what the run's tool calls did not do), all 31 ran again on 54d25dd: 27 passed (`benchmarks/results/workflows_twin_general_54d25dd.json`). focus_series still leaves the defocus at +20 nm but now says it did not confirm the reset instead of claiming it; one note was a false alarm (describing an earlier image as "acquired"), since fixed; explore_then_zoom imaged without moving to the region. A fresh clone on Ubuntu (WSL2) passed every quickstart step (989 tests, check_stack 22/22, the GUI contract, the mapping agent) in about 20 minutes. A fresh clone of 6bc0e93 followed the quickstart without changes: sync (with its documented Windows fix), tests, the background start recipe, both checks and both agent commands. Raw rows: `benchmarks/results/workflows_twin_general_*.json`.

**Live checks**, each run on the stack after every change: `startup_scripts/check_stack.py` passes 22/22 (map, stitch, score, POIs, approval hold/approve/single-use, a held map start showing its plan) and `startup_scripts/check_gui_contract.py` passes 13/13 (SciAgentGUI's approvals and map/spectrum reads). The SciAgentGUI desktop app was also driven against the live stack, last on asyncroscopy 01006e9 with sciagentgui 4f0343e. It listed the stitched maps, including re-stitched versioned keys and 324-tile maps shown as pyramid previews. On an EDS map it showed the scored candidates (score, scorer version, reason) and the 16 EDS points, and one point opened its spectrum. It switched the instrument to approve mode and displayed a held `Mapper_start` with its plan. Once that start was approved in the GUI, the retried start ran 9 tiles and the stitch, and the GUI switched the instrument back to auto. That round found a GUI bug, fixed in 4f0343e: on a small map the EDS points could never be clicked, because density mode counted empty grid cells.

## Not claimed

- No learned reward, no human-preference data.
- No identity from WG1's token service yet (the endpoints can verify its tokens; only development tokens have been used) and no Kubernetes deployment (WG1).
- No nanoindentation or SPM schemas.
